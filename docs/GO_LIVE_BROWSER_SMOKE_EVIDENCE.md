## Evidence Rules

- Record desktop and mobile viewport for each launch-critical workflow.
- Record account role used.
- Record expected and actual result.
- Record console errors and failed network requests.
- Mark workflow failed if a required control is inaccessible, hidden, unauthenticated incorrectly, or silently stale.

## Staging Evidence Preflight

The staging blocker now has an executable preflight gate:

```bash
npm run go-live:staging-preflight
```

The command is intentionally read-only. It fails closed unless the run uses production-like staging policy (`STATLY_RUNTIME_ENV` is not local, bypass auth is disabled, admin/cron/ETL tokens and Firebase admin credentials exist) and provides a HTTPS non-local staging URL, smoke account, fixture league and draft IDs, read-only mutation scope, cleanup policy, monitoring URL, release/build ID, and the full required browser matrix declaration. When those inputs are present, it performs safe `GET` checks for public entry, auth entry, player/ranking routes, fixture league/draft routes, and anonymous admin denial, then blocks on any server error.

After staging smoke evidence is captured, validate the release artifact with:

```bash
npm run go-live:evidence-check -- --file <evidence.json>
```

Use `docs/go-live-evidence.example.json` as the fill-in contract for the release artifact, or generate a release-specific draft with:

```bash
npm run go-live:evidence-check -- --init \
  --release-id <release-id> \
  --base-url <staging-url> \
  --smoke-account <smoke-account-email> \
  --league-id <staging-league-id> \
  --draft-id <staging-draft-id> \
  --output <evidence.json>
```

Generated drafts use `not-run` statuses and intentionally fail validation until real release evidence is filled in. For non-example releases, placeholder URLs such as `replace-with-evidence-url`, `.example` domains, or angle-bracket placeholders are rejected. The check requires release metadata (`releaseId`, `commitSha`, `testDate`, `tester`), staging fixture identity (dataset version, smoke account, league ID, draft ID), command evidence for `npm run typecheck`, `npm run lint`, `npm run guard:routes`, `npm run guard:design`, `npm test`, and `npm run branch:complete`, route coverage for the launch-critical public/protected/admin-denial routes, desktop and mobile accessibility proof, the required browser matrix, desktop and mobile P0 workflows, production-like Web Vitals, degraded-state proof, actionable accepted risks, closed or explicitly accepted launch blockers, and a final launch recommendation with rationale, rollback plan, and post-deploy smoke plan.
